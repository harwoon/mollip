# 사이드바 그룹 목록 모달 설계

## 목적

일반 사용자가 사이드바의 그룹 메뉴에서 그룹 페이지로 이동하지 않고도 전체 일반 그룹의 색상, 이름, 조건시간을 빠르게 확인할 수 있게 한다.

## 범위

- 사이드바 그룹 메뉴 오른쪽에 정보 버튼을 추가한다.
- 정보 버튼을 누르면 그룹 목록 모달을 연다.
- 휴면 그룹은 목록에서 제외한다.
- 그룹 색상, 그룹명, 조건시간만 표시한다.
- 그룹 조건시간이 높은 순서로 정렬한다.
- 기존 그룹 목록 API와 공통 모달을 재사용한다.

그룹 생성·수정, 그룹 상세 정보, 사용자의 그룹 이동 기능은 포함하지 않는다.

## UI와 상호작용

### 정보 버튼

- `그룹` 내비게이션 링크의 오른쪽 끝에 원형 `i` 아이콘 버튼을 배치한다.
- 버튼에는 그룹 목록을 연다는 의미의 접근 가능한 이름을 제공한다.
- 버튼 클릭은 그룹 링크의 페이지 이동과 분리한다.
- 키보드 포커스와 hover 상태를 제공한다.

### 모달

- 프로젝트의 공통 `AppModal`을 사용한다.
- 제목은 `그룹 목록`으로 표시한다.
- 헤더 아래에 `그룹명`, `그룹 조건 시간(h)` 열을 둔다.
- 각 행은 그룹 색상을 나타내는 점, 그룹명, 조건시간을 표시한다.
- 조건시간은 초 단위 `groupTime`을 시간으로 변환하여 `90시간`, `5시간` 형태로 표시한다.
- 목록이 모달의 최대 높이를 넘으면 목록 영역만 세로 스크롤한다.
- 헤더의 닫기 버튼, 오버레이 클릭, `Esc` 키로 닫을 수 있다.

## 컴포넌트 구조

- `Sidebar`
  - 그룹 정보 버튼의 클릭 상태를 관리한다.
  - 모달의 열기와 닫기를 제어한다.
- `GroupListModal`
  - 그룹 목록 조회 및 화면 상태를 담당하는 전용 컴포넌트다.
  - `open`, `onClose`를 입력으로 받는다.
  - 공통 `AppModal` 안에 목록을 렌더링한다.
- 그룹 API 모듈
  - 기존 `GET /group/groups` 호출 함수를 추가한다.
  - 인증 토큰을 기존 그룹 API와 같은 방식으로 전달한다.

전용 모달 컴포넌트로 데이터 조회와 목록 표현을 사이드바에서 분리하여 `Sidebar`의 책임과 크기 증가를 제한한다.

## 데이터 흐름

1. 사용자가 사이드바의 정보 버튼을 누른다.
2. `Sidebar`가 모달을 연다.
3. `GroupListModal`이 열린 시점에 `GET /group/groups`를 호출한다.
4. 응답의 `groups`에서 휴면 그룹을 제외한다.
5. 유효한 `groupTime` 숫자를 기준으로 내림차순 정렬한다.
6. 각 그룹을 색상, 이름, 시간으로 변환해 표시한다.

휴면 그룹 판별은 환경별 ID에만 의존하지 않도록 현재 휴면 그룹 ID와 정규화한 그룹명 `휴면그룹`을 함께 확인한다.

## 상태와 오류 처리

- 조회 중: 목록 영역에 로딩 문구를 표시한다.
- 조회 실패: 사용자용 오류 문구와 다시 시도 버튼을 표시한다.
- 빈 목록: 표시할 그룹이 없다는 문구를 표시한다.
- 잘못된 색상값: 기본 중립 색상을 사용한다.
- 잘못된 조건시간: `0시간`으로 안전하게 표시한다.
- 모달을 닫은 뒤 다시 열면 최신 그룹 설정을 반영하도록 다시 조회한다.

## 접근성

- 정보 버튼은 실제 `button` 요소로 구현하고 `aria-label`을 제공한다.
- 공통 모달의 포커스 이동, 포커스 트랩, `Esc` 닫기, 닫힌 후 포커스 복원을 재사용한다.
- 색상만으로 그룹을 구분하지 않고 그룹명을 함께 표시한다.
- 표 형태의 열과 행 관계가 보조기술에도 전달되도록 의미 있는 마크업을 사용한다.

## 테스트와 검증

- API 함수가 성공 응답을 반환하고 실패 응답에서 오류를 던지는지 확인한다.
- 휴면 그룹 제외, 조건시간 내림차순 정렬, 초에서 시간으로의 표시 변환을 확인한다.
- 정보 버튼 클릭이 그룹 페이지 이동 없이 모달만 여는지 확인한다.
- 닫기 버튼, 오버레이, `Esc`로 닫히는지 확인한다.
- 로딩, 오류, 빈 목록 상태를 확인한다.
- 프론트엔드 lint와 production build를 실행한다.
